# Core Runtime, Procedural Macros, and Composable Transports

* **Status:** Current
* **Last Updated:** 2026-11-14
* **Scope:** `chromatofoor`, `chromatofoor-derive`, `esdm`, `chromatofoor-http`, `chromatofoor-graphql`, `chromatofoor-mcp`, `chromatofoor-tui`, `chromatofoor-tauri`

---

## 1. Overview & Problem Statement

Chromatofoor maps the 18 modeling kinds of the Event-Sourced Domain Model (`schemas/core/v1.yaml`) plus its extension schemas (`lifecycle/v1`, `given-when-then/v1`, `infrastructure/v1`, `domain-storytelling/v1`) onto `architecturekit` primitives (`State`, `Decider`, `Event`, `Events`, `Projection`, `InMemoryView`, `Store`, and `Precondition`).

Both hand-written Rust domains and workspaces generated by `chromatofoor-gen` use the same `#[chromatofoor::<kind>]` attribute macros and runtime traits, avoiding parallel framework dialects or runtime code-generation shims.

---

## 2. Core Architecture & Design Decisions

### 2.1 Pure-Functional `architecturekit` Alignment & Storage Decoupling
- **Mechanism**: Consistency units (`Aggregate` and `DynamicConsistencyBoundary`) implement `architecturekit::State`. Commands implement pure decision logic (`Command::decide(self, state: &S) -> Result<Vec<S::Event>, Self::Error>`), and events implement pure state transitions (`Event::evolve(&self, state: A) -> A`).
- **Storage Boundary**: `chromatofoor` contains no filesystem or external database storage implementations of its own; persistence delegates to `architecturekit::Store` (`architecturekit::EventStore` implementations such as `eventsourcingdb::Client` and `chromatofoor::InMemoryEventStore`).
- **No `#[cfg(test)]` in `chromatofoor/src`**: Behavioral and compile-fail tests for core traits and macros live as executable rustdoc doctests (`cargo test -p chromatofoor --doc`) and integration tests.
- **Macro Dependency Hygiene**: `#[chromatofoor::<kind>]` expansions emit `#[architecturekit(crate = "chromatofoor::architecturekit")]` and `#[validate(crate = "chromatofoor::validator")]` so downstream crates depend only on `chromatofoor` without adding direct `architecturekit` or `validator` dependencies.

### 2.2 Hierarchical `/<domain>/...` Scope Paths (`Kind` & `Topic`)
- **Mechanism**: Every ESDM kind implements `chromatofoor::common::Kind` (`type Scope`, `KIND`, `NAME`, `TOPIC`, `DESCRIPTION`). `TOPIC` is derived mechanically from the scope chain using `/`-delimited kebab-case segments:
  - **Domain**: `/<domain>`
  - **Subdomain**: `/<domain>/<subdomain>` (orthogonal strategic grouping; bounded contexts remain scoped directly to `Domain`)
  - **Bounded Context**: `/<domain>/<bc>`
  - **Aggregate / DCB**: `/<domain>/<bc>/<unit>`, instance subject `/<domain>/<bc>/<unit>/<id>`
  - **Event / Command**: `/<domain>/<bc>/<unit>/<name>` (or `/<domain>/<bc>/<event>` for freestanding BC events)
  - **Read Model / Query**: `/<domain>/<bc>/<name>`
  - **Policy / Event Handler / Process Manager / Timer**: `/<domain>/policies/<name>`, `/<domain>/event-handlers/<name>`, `/<domain>/process-managers/<pm>/<id>`, `/<domain>/timers/<timer>/<id>`
- **Trade-off**: `DomainBuilder<D>` verifies domain membership via `const { assert!(topic_in_domain(D::TOPIC, ...)) }` so crates sharing the same domain topic path compose cleanly across multi-crate workspaces.

### 2.3 Compile-Time Identity (`Identified`) & Lifecycle Preconditions (`lifecycle/v1`)
- **Mechanism**:
  - `Identified` (`IdSource::Generated`, `State`, `CommandPayload`, `Schema`, `Static`) mirrors `identifiedBy` in `schemas/core/v1.yaml`.
  - Identifier fields must use validated segment types (`uuid::Uuid`, `chromatofoor::Identifier`, or `chromatofoor::SubjectSegment`) implementing `ValidIdField` / `FieldAsIdStr` to prevent `/` injection or empty subject segments.
  - Because `schemas/core/v1.yaml` is closed (`unevaluatedProperties: false`), aggregate command lifecycles (`created` vs. mutating, plus optional `deleted`) are declared in `schemas/lifecycle/v1.yaml` (`kind: aggregate-lifecycle`) and verified by `esdm::lint::validate_model` and `validate_command_id_fields` at compile time.
  - Creation commands (`#[lifecycle(create)]`) attach `[Precondition::on_state_read()]` (pristine subject check); mutation commands attach `[Precondition::on_populated_subject(subject), Precondition::on_state_read()]` so mutations against non-existent aggregate streams fail closed.

### 2.4 Dynamic Consistency Boundaries (`DynamicConsistencyBoundary`)
- **Mechanism**: `#[chromatofoor::dynamic_consistency_boundary(scope = <BC>, identified_by = [...], events = [...])]` spans ad-hoc consistency across multiple event streams per decision without a persistent container aggregate.
- Commands targeting a DCB implement `Command::matches(&self, event)` to fold consulted events directly from `architecturekit::Store` into ephemeral decision state, failing at compile time (`#[diagnostic::on_unimplemented]`) if required event conversions are missing.

### 2.5 Fail-Closed Actor Authorization (`Actor` & `Authorized`)
- **Mechanism**: Commands and queries declare allowed `Actor` types (`actors = [...]` or per-variant `#[actors(...)]` on command enums).
- **Security Invariant**: Empty `ALLOWED_ACTORS` means **no external actor access** (`Authorized::is_authorized_for` returns `false`, and `DomainRuntime::dispatch_command` / `dispatch_query` return `DispatchError::Unauthorized`). Runtime dispatch enforces both type-level pre-checks and post-deserialization instance checks (`ensure_authorized_instance`) so enum variant restrictions cannot be bypassed. Public access must be modeled explicitly via a dedicated actor (e.g., `guest` or `public`).

### 2.6 Read Models (`DocumentView`), Policies, Event Handlers, and Outbox Process Managers
- **Read Models (`ReadModel` & `Project<E>`)**: `#[chromatofoor::read_model(scope = <BC>, events = [...])]` implements `architecturekit::Projection` over declared events. `DocumentView<T>` wraps string-keyed `InMemoryView` projections with `upsert`, `upsert_subject`, `get`, `all`, and `latest`.
- **Policies (`Policy` & `React<E>`)**: Domain-scoped `EventConsumer`s that react to events and execute follow-up commands via `execute_policy_command` (isolating `Error::Decider` domain rejections while propagating `Error::Transient` infrastructure failures for retry).
- **Process Managers (`ProcessManager`, `OnEvent`, `OnTimer`)**:
  - Stateful sagas correlated via `correlated_by = event_field(<field>)` or `correlated_by = event_subject`.
  - **Outbox Durability**: Before executing outbound `ProcessCommand`s, `save_process_instance` persists updated saga state and `pending_commands` to `/<domain>/process-managers/<pm>/<id>`; `flush_process_commands` then dispatches commands with transient conflict retry and clears the outbox on completion.
  - **Timers (`ProcessTimer`)**: `supervise_process_timers` schedules deadlines in `/<domain>/timers/<timer>/<id>` with bounded exponential backoff and validates `deadline` on `ProcessTimerFired` before invoking `OnTimer::on_timer`.

### 2.7 Compile-Time Schema Reflection (`DomainRuntime`) & Composable `Presentation`
- **Runtime Introspection**: `DomainBuilder<D>` registers commands (`CommandDescriptor`), read models (`ReadModelDescriptor`), queries (`QueryDescriptor`), and consumers (`ConsumerDescriptor`), exposing JSON Schema catalogs, actor-filtered operations, command/query JSON dispatch, and SSE event subscriptions via `DomainRuntime` (without embedding static YAML strings).
- **Two-Tier Transport Composition**:
  - `chromatofoor::domain::Presentation` attaches standalone transports (`chromatofoor_http::HttpServer`, `chromatofoor_mcp::Mcp::stdio()`, `chromatofoor_tui::Tui`) to `DomainBuilder::attach(...).serve()`.
  - `chromatofoor_http::HttpProtocol` mounts HTTP sub-protocols (`chromatofoor_graphql::GraphQL`, `chromatofoor_mcp::Mcp::http()`) onto a single `HttpServer` listener and router, keeping `chromatofoor-mcp` free of `axum` unless its `http` feature is enabled.

### 2.8 Given-When-Then Specification Harness (`chromatofoor::testing`)
- `testing::given::<S>(history)` tests both `Aggregate` and `DynamicConsistencyBoundary` decisions, including `when_as::<Actor, _>()` authorization checks.
- `testing::given_process_manager::<P>(history)` tests event/timer transitions, emitted `ProcessCommand`s, `SetTimer`/`CancelTimer` actions, state assertions, and termination (`then_ended()`).
- `testing::given_read_model(rm, history)` tests event projection folding and authorized `Query` execution.
